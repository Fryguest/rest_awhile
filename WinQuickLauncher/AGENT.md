# Agent 工作上下文

本文供维护 WinQuickLauncher 的代码 agent 阅读，不是用户使用手册。
以当前代码和用户最新明确要求为准；本文不构成修改、执行脚本或提交代码的授权。

## 变更原则

- 先阅读相关实现、调用方和事件绑定，再提出修改。
- 展示修改范围和完整 diff，获得明确执行确认后再写文件。
- 仅修改指定部分，不顺手重构、格式化、迁移数据或更新历史文档。
- 不因函数只有一个引用就删除：AHK 热键、OnEvent、OnMessage、SetTimer 和 OnExit 都可能是入口。
- 不擅自运行会写注册表、注入键鼠输入、覆盖个人数据的代码。
- 不创建隐藏产物。图标放 `ico/`，日志放 `logs/`，临时测试使用可见目录。
- 沟通简洁、中文优先；命令尽量保持单行；不使用 emoji。
- 本文列出的限制是上下文，不是要求立即修复的任务。

## 文件定位

| 文件 | 职责 |
|---|---|
| `run.ahk` | 主入口、启动器窗口、显示器选择、设置、启动项目和原启动器右键菜单 |
| `util.ahk` | 调试日志、录制/回放日志会话、创建日志目录 |
| `recorder.ahk` | Raw Input 录制、TSV 录制文件、真实键鼠回放和输入清理 |
| `memo.ahk` | 备忘录窗口、卡片、分组、编辑、操作事务及恢复日志接入 |
| `memo-core.ahk` | 备忘录模型、校验、周期计算、TSV 存储及恢复日志格式 |
| `setup.ahk` | 安装/卸载文件与目录的 Windows 右键菜单 |
| `add.ahk` | 接收路径参数，去重后追加到启动器项目列表 |
| `test/sleep-test.ahk` | Windows 等待策略的计时/CPU 基准，不是功能测试套件 |
| `ico/` | 所有运行时 ICO 资源 |
| `misc/` | 历史说明、设计、TODO 和已知问题 |

依赖关系：

```text
run.ahk -> util.ahk、recorder.ahk、memo.ahk
recorder.ahk -> util.ahk
memo.ahk -> memo-core.ahk
```

没有包管理或编译构建流程。代码使用 AutoHotkey v2 语法，并依赖 Windows GUI 和 Win32 API。

## 入口与运行副作用

- 运行入口是 `run.ahk`，资源和数据路径通常基于入口脚本的 `A_ScriptDir`。
- `recorder.ahk` 也能独立运行；被 Include 时会立即设置进程 DPI 感知、创建隐藏 Raw Input 接收窗口、注册消息和退出回调。
- `util.ahk` 被 Include 时尝试创建 `logs/`。
- `setup.ahk` 的安装/卸载回调会写删 HKCU 注册表；不能把它当无副作用的测试脚本运行。
- `add.ahk` 会修改 `items.txt`。
- F7 会发送真实键鼠输入；不得自动回放不可信录制文件。
- `run.ahk` 的自动重载只比较入口脚本自身的修改时间，不监听 Include 文件。修改模块后应手动重启脚本。
- 不在未确认的情况下运行第二个实例；`#SingleInstance Force` 可能替换正在运行的实例，丢失内存中的录制。

## 启动器约束

- Ctrl+1 显示/隐藏启动器；使用鼠标所在显示器。
- `BgGui` 是背景层，`ContentGui` 是重建的内容层。
- 重建或隐藏内容时，先清理备忘录及弹窗，再销毁父窗口。
- 启动器项目是双击打开；备忘录事项是单击编辑，不要混淆。
- 启动器自身的右键菜单仍存在，包含打开目录、复制路径和从列表删除项目。
- 删除启动器项目不是删除文件，也不是删除备忘录事项。
- `run.ahk` 中用于关闭右键菜单的定时器不属于备忘录周期轮询，不能一并移除。
- `setup.ahk` 的注册表图标路径与 `ico/ico.ico` 保持一致；修改安装脚本不会自动更新已经安装的注册表项。

## 备忘录：已确定的产品约束

### 界面和操作

- 使用固定的 4K、Windows 150% 缩放基准布局，不做动态分辨率/DPI 适配。
- 保留显示器原点 `ScreenX/ScreenY`，用于在所选显示器定位。
- 尺寸与卡片样式入口是 `Memo_Layout`、`Memo_CardStyle`，不要重新引入散落的缩放逻辑。
- 三组顺序固定为每天、每周、单次；空组和每页的三个标题都要显示。
- 先根据组状态过滤，再分页；目前每页最多 13 张卡片，三个组共用分页。
- 同组未完成优先，其余保持数组顺序；新增事项插入数组开头。
- 每组添加按钮在组名左侧；显示状态按钮在右侧。
- 三态为 `all -> open -> hidden -> all`，各组独立；仅保存在内存中，重启恢复全部显示。
- 隐藏组只隐藏事项，不能隐藏组标题和按钮。
- 单击事项文字编辑，单击方框切换完成状态。
- 添加时周期由来源组决定；添加和编辑窗口均不允许更改周期。
- 每周事项可以修改刷新日，默认周一。周期显示为只读文字。
- 每日和每周的零点恢复提示已删除，不要擅自加回。
- 调整字号时同时检查控件高度；组名曾因固定高度过小而被裁切。

### 不要无需求恢复的旧功能

备忘录没有标签、自定义周期、完成日期、完成历史、日期确认弹窗、自定义右键菜单或删除入口。
不要根据旧 README 或历史代码把这些功能重新加入。
启动器自己的右键功能不受此限制。

### 周期与事务

- 只有单次、每天、每周；重复间隔只允许 1 或 7 天。
- 使用 Windows 系统本地时间，时间戳格式为 `yyyyMMddHHmmss`，不存时区。
- 每日在本地零点刷新；每周在选定周几的本地零点刷新。
- 选择今天作为新的每周刷新日时，安排到下周，而不是当天已经过去的零点。
- 不进行周期定时轮询。启动、打开启动器、打开编辑框和数据操作时按需检查。
- 周期从原刷新锚点推进，离线跨过多个周期时直接计算新边界，不从启动时刻重新计时。
- 周期到期会清除完成状态；单次事项不会自动清除。
- 编辑文字不重新安排周期。编辑每周刷新日仅重算下一次刷新时间，编辑操作本身不清除完成状态。
- `Memo_Transact()` 复制候选状态、推进周期、执行修改、保存成功后才发布内存状态。
- 不直接修改 `Memo_Tasks` 来绕过事务。
- `MemoCore_CopyTasks()` 使用 `Clone()`，因为当前字段都是标量；新增嵌套对象时必须重新评估复制语义。
- 勾选和分组切换采用一次性 `SetTimer` 延迟处理，避免在相关控件回调中销毁当前控件；这些不是周期轮询。
- 保留跨周期校验：过期卡片上的操作可能要求用户重试，不能把旧周期操作直接套到新周期。

## 备忘录数据格式

正式数据是 `memo-data.tsv`，当前写入格式：

```text
WQLMEMO<TAB>3
TASK<TAB>Id<TAB>Kind<TAB>IntervalDays<TAB>NextRefresh<TAB>CycleStart<TAB>Done<TAB>CreatedAt<TAB>Title
```

- `TASK` 行含首字段在内共 9 列。
- `Kind` 是 `once` 或 `recurring`；单次间隔为 0、刷新时间为空。
- `Done` 是 0 或 1；周几从 `NextRefresh` 推导，没有独立存储字段。
- 标题为 1～120 个字符，不允许制表符或换行；ID 必须唯一。
- 字符串转义统一使用 `MemoCore_Escape/Unescape`，不要另造 CSV 或 JSON 编码。
- 读取兼容 WQLMEMO 1/2/3；旧完成日期、历史和标签不会恢复到当前模型。旧自定义间隔可能被当前校验拒绝，不自动转换。
- 保存先写同目录 `.tmp`，校验写入字节数并 Flush，再用 MoveFileExW 替换正式文件。
- 不生成 `.bak`；读取失败时保留原文件并阻止编辑。
- 不擅自修改格式版本或自动迁移现有个人数据。

## 恢复日志

路径：`logs/memo-journal.log`。它不是调试日志，不受 `debug` 控制。

- 仅成功保存的添加、编辑操作生成增量，action 为 `add` 或 `edit`。
- 完成/撤销完成、自动周期刷新、打开/取消、翻页和分组切换都不生成增量。
- 每条增量包含时间和受影响事项的完整 TASK 行，不是整个 TSV。
- 不生成首次快照；从空白、计数 0 开始。
- 每累计 100 条增量，追加当前完整快照并归零。
- 启动时扫描一次日志，接续最后完整快照之后的增量计数。当前计数实现保持现状，不擅自优化。
- TSV 保存成功后直接 FileAppend；追加失败被忽略，不做回滚、重试或跨文件事务。
- 日志含事项正文，属于个人数据。没有轮转、自动清理或自动恢复工具。

格式：

```text
DELTA<TAB>yyyy-MM-dd HH:mm:ss<TAB>add或edit
TASK<TAB>...
END<TAB>DELTA
SNAPSHOT<TAB>yyyy-MM-dd HH:mm:ss
WQLMEMO<TAB>3
TASK<TAB>...
END<TAB>SNAPSHOT
```

恢复语义：
1. 有完整快照时从最后一份开始，没有时从空集合开始。
2. 按顺序重放后续完整增量，以 ID 新增或覆盖事项；新增保持插入开头的顺序。
3. 最后按当前时间推进周期。
4. 完成状态只能恢复到最近被记录的状态，这是已接受的取舍。
5. 启用日志前已存在、之后未编辑的事项，在第一份快照前无法从日志恢复。

`MemoCore_JournalCount()` 只负责计数，不是恢复函数。
若开发恢复工具，先输出到新的可见文件供检查，不默认覆盖正式 TSV。

## 录制与回放

- 全部公开状态和函数使用 `Rec_` 前缀，避免与主入口和备忘录全局变量冲突。
- F6 切换待录制/停止；F7 开始/请求停止回放。
- 状态为 `idle / armed / recording / save_pending / replaying`。
- armed 状态等到首个有效事件才开始计时；抬起事件不能作为首个有效输入。
- 采集使用 Raw Input，QPC 生成微秒级偏移。高频采集路径不要新增文件 IO、弹窗或重型处理。
- 只记录键盘、鼠标按钮和滚轮；不记录纯鼠标移动轨迹，不能承诺真实拖拽轨迹回放。
- 停止录制时丢弃未闭合输入，不能擅自用停止时刻伪造其松手时间。
- 保存失败进入/保留 `save_pending`，数据留在内存供再次按 F6 重试；退出或重载可能丢失，不能宣称退出会自动保存。
- `Rec_Configure()` 设置录制文件和重复次数；0 次数代表无限回放。
- 回放按绝对 QPC 目标时刻等待，优先使用高精度 waitable timer，失败时回退 Sleep。
- 生产等待策略与 `test/sleep-test.ahk` 中的实验策略不是同一回事，不根据报告擅自替换。
- 每轮及回放结束时，只释放本次回放跟踪的按键/鼠标按钮；不要释放其他真实用户输入。

录制文件以 `WQLREC<TAB>1` 开头，包含 VSCREEN、MONITOR、EVENT 行。
EVENT 时间偏移单位为微秒，类型包括 KD/KU、MD/MU、W/HW。
当前 `Rec_LoadRecording()` 按字段直接解析，不是完整 schema 或安全校验器；不要把不可信文件直接交给真实回放。

## 文件保护与历史资料

- `items.txt`：个人启动器项目；`add.ahk` 大小写不敏感去重，`run.ahk` 加载时过滤不存在的路径。
- `config.txt`：IconSize、Opacity、RecordingFile、ReplayCount。
- `recording.tsv` 及配置指定的其他录制文件、`memo-data.tsv`、`logs/` 均视为个人运行数据，不擅自覆盖、删除或提交。
- 不因为移动日志目录就修改 `items.txt`；用户明确要求该文件不随日志路径调整。
- 所有运行时图标位于 `ico/`，包括启动器/注册表使用的 `ico/ico.ico`。
- `misc/README.md` 的备忘录描述已过时，包含旧标签、历史、备份和界面设计，不能作为当前功能规范。
- `misc/recorder-design.md` 是历史设计参考；先核对当前 recorder 实现再使用其中的结论。
- `misc/TODO.md` 和 `misc/known-issues.md` 不是执行授权，不顺手完成其中任务。

## 验证与交付

先做只读检查：

```text
git status --short
git diff --check
git diff --cached --stat
```

没有通用单元测试或 CI 入口。不要把文本扫描、Python 模型检查或等待基准称为 AutoHotkey 功能测试。

在具备解释器的 Windows 环境手动验证，执行前说明副作用：
- 启动器：Ctrl+1、Esc、设置切换、项目双击和原右键菜单。
- 备忘录：空组、三态、分页、按组添加、单击编辑、周期只读、每周刷新日、勾选保存/失败及跨周期操作。

- 日志：添加/编辑写一条增量，勾选/自动刷新不写；第 99/100/101 条、重启接续、空行和未完成尾记录。
- 周期：本地零点、周几换算、选今天到下周、跨月/跨年/离线周期推进。
- 录制回放：必须在受控窗口验证，避免无限播放；确认停止、失败重试和悬挂输入清理。

缺少 Windows/AutoHotkey 时明确报告未运行，不虚构界面、注册表、键鼠回放或计时验证结果。
